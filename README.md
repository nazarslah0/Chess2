# Chess2 — محلل ومراجع مباريات شطرنج احترافي (Flutter)

تطبيق Flutter يعمل بمحرك **Stockfish 19** حقيقي (ثنائي مُصرَّف من المصدر،
ليس محاكاة ولا بيانات وهمية)، لتحليل الوضعيات والمباريات الكاملة بما يشمل
تصنيف النقلات والرسم البياني للتقييم وتقرير مباراة متكامل.

## الميزات

### تحليل الوضعية
- رقعة Staunton-style حقيقية (`CustomPainter`، ليست رموز نصية)، عدة ثيمات رقعة/قطع.
- تحريك القطع بالنقر أو بالسحب (Drag & Drop)، إحداثيات اختيارية، Dark/Light mode.
- تحليل Stockfish 19 حقيقي: عمق قابل للتعديل، MultiPV، سهم أفضل نقلة من UCI مباشرة.
- إعداد وضعية يدويًا من الصفر (لوحة قطع) بجانب وضع اللعب الكامل القواعد.

### تحليل مباراة (PGN)
- استيراد/لصق PGN، أو تحميل مباريات **Chess.com** و**Lichess** (API عام،
  بلا تسجيل دخول ولا كلمات مرور).
- تحليل كامل للمباراة نقلة-نقلة، مع شريط تقدّم وإمكانية **إلغاء التحليل**
  مع الاحتفاظ بما تم تحليله فعليًا.
- **تخزين مؤقت (Session Cache)**: إعادة فتح نفس المباراة بنفس إعدادات
  المحرك خلال نفس الجلسة لا يُعيد تشغيل Stockfish إطلاقًا.
- تصنيف النقلات (رائعة!! / الأفضل / ممتازة / جيدة / غير دقيقة / خطأ /
  خطأ فادح / فرصة ضائعة) بفارق تقييم حقيقي محسوب من Stockfish، وليس
  تخمينًا.
- "أفضل نقلة في المباراة" (Best Engine Move) و"نقلة رائعة!!" (Brilliant)
  **قسمان منفصلان تمامًا** — الأولى تطابق bestUci فعليًا، والثانية تتطلب
  إضافة لذلك: تضحية حقيقية، عدم كونها إجبارية، وفارقًا واضحًا عن ثاني
  أفضل نقلة (multiPV=2) حتى لا تُطلَق بسهولة.
- التنقل: ⏮ ◀ ▶ ⏭، قائمة نقلات قابلة للنقر، Slider، سحب يمين/يسار على
  الرقعة — كل ذلك يعتمد على FEN محفوظ مسبقًا لكل نقلة، بلا أي إعادة
  تحليل أو إعادة توليد عند كل ضغطة.
- دقة "Chess2 Accuracy" (موسومة صراحة بأنها مقياس خاص بالتطبيق، ليست
  مطابقة لدقة Chess.com) + **ACPL** (متوسط خسارة التقييم بالقرن) لكل لاعب.

### تقرير المباراة (Game Report)
تبويب داخل شاشة التحليل نفسها (وليس شاشة منفصلة — تفاديًا لإعادة تشغيل
Stockfish عند فتحه):
- بيانات المباراة، ملخص نصي مبني من أرقام حقيقية فقط (لا نص وهمي).
- إحصائيات لكل لاعب: الدقة، ACPL، عدد كل تصنيف نقلة.
- **رسم بياني للتقييم** (مرسوم يدويًا بدون مكتبات خارجية)، نقاط ملوّنة
  عند الأخطاء، قابل للمس/السحب للانتقال لأقرب نقلة.
- أفضل نقلة، أسوأ نقلة، فرص ضائعة، لحظات حرجة — كل عنصر قابل للضغط
  وينقل مباشرة لنفس شاشة التحليل عند تلك النقلة (بلا تحليل إضافي).
- تحليل مراحل المباراة (افتتاح/وسط/نهاية): عدد نقلات، دقة، أخطاء لكل مرحلة.

### الصوت
move / capture / check / checkmate / castle / promotion / game_over —
كل صوت يُشغَّل تلقائيًا حسب نوع النقلة الفعلي.

## معمارية Stockfish 19
**لا** تُستخدم حزمة `stockfish_chess_engine` (FFI). بدلاً من ذلك، يبني
الـ CI (`.github/workflows/build.yml`) محرك Stockfish 19 من المصدر
الرسمي، ويُعبّأ كمكتبة أصلية (`jniLibs/arm64-v8a/libstockfish.so`) ليُشغَّل
كعملية فرعية حقيقية عبر MethodChannel مخصص (`lib/engine_service.dart`).
هذا يتطلب `android:extractNativeLibs` / `useLegacyPackaging` مفعَّلًا
(يُضبط تلقائيًا في الـ workflow) وإذن `INTERNET` لميزتي Chess.com/Lichess.

## هيكل المشروع
```
lib/
  main.dart                 # نقطة الدخول + PositionAnalyzerScreen (تحليل وضعية)
  home_screen.dart           # الشاشة الرئيسية (القائمة الأساسية)
  models.dart                 # GameState (يغلّف حزمة chess) + الثيمات
  engine_service.dart         # غلاف UCI حول محرك Stockfish 19 الأصلي
  board_widget.dart           # رسم الرقعة + الأسهم + Drag & Drop
  piece_painter.dart          # رسم القطع الحقيقية (Staunton)
  panels.dart                 # لوحات تحليل الوضعية الفردية
  sound_service.dart          # أصوات الحركة/الأكل/الكش/الكش مات/...

  pgn_utils.dart               # تفكيك PGN إلى نقلات حقيقية (FEN قبل/بعد كل نقلة)
  pgn_import_screen.dart       # لصق/استيراد PGN يدويًا
  uci_utils.dart                # تحليل/مقارنة دقيقة لنقلات UCI (from/to/promotion)

  game_analysis_screen.dart     # شاشة مراجعة/تحليل المباراة + تقرير المباراة (موحّدة)
  game_review_models.dart       # تصنيف النقلات (MoveQuality) + كشف "رائعة"
  analysis_result.dart          # نموذج MoveAnalysisResult الموحّد لكل نقلة محلَّلة
  analysis_cache.dart           # تخزين مؤقت للتحليل داخل الجلسة

  my_games_screen.dart          # اختيار Chess.com أو Lichess
  game_review_screen.dart       # بحث مباريات Chess.com
  chesscom_service.dart         # Chess.com Public API
  lichess_screen.dart           # بحث مباريات Lichess
  lichess_service.dart          # Lichess Public API

.github/workflows/build.yml     # بناء Stockfish 19 + APK تلقائيًا على GitHub Actions
```

لا توجد مجلدات `android/` أو `ios/` في هذا الريبو — تُولَّد تلقائيًا أثناء
البناء عبر الـ workflow.

## ملاحظة معمارية صريحة
`game_analysis_screen.dart` لا يزال ملفًا كبيرًا نسبيًا، وبعض منطق تحليل
المباراة لا يزال يعتمد داخليًا على مصفوفات متوازية مفهرسة بدل استخدام
`MoveAnalysisResult` كتمثيل أساسي وحيد في كل مكان (لأسباب أداء التنقل
الفوري بين النقلات). إعادة الهيكلة الكاملة إلى مجلدات منفصلة
(`analysis/`, `models/`, `screens/`, `widgets/`) خطوة مستقبلية آمنة لم
تُنفَّذ بالكامل بعد تفاديًا لمخاطرة نقل آلاف الأسطر بين ملفات بلا بيئة
Flutter محلية للتحقق من عدم كسر أي استيراد.

## البناء والتشغيل محليًا
```bash
flutter create --platforms=android .   # أول مرة فقط
flutter pub get
flutter run
```

## البناء عبر GitHub Actions
1. ارفع المشروع إلى مستودع GitHub وادفع إلى فرع `main`.
2. سيبني الـ workflow Stockfish 19 من المصدر + APK تلقائيًا.
3. من تبويب **Actions**، افتح آخر تشغيل ناجح وحمّل الـ Artifact.
4. لإصدار على صفحة Releases: `git tag v1.0.0 && git push origin v1.0.0`.

`flutter analyze` يُشغَّل كخطوة **تفشل البناء** عند وجود أي خطأ حقيقي
(لم يعد مخفيًا بـ `|| true`).

## ملاحظة أمانة
لا تتوفر لديّ بيئة Flutter محلية لتشغيل `flutter pub get` /
`flutter analyze` / `flutter build apk` والتحقق فعليًا قبل التسليم —
هذا بالضبط ما يفعله GitHub Actions عند أول دفع. إن ظهر أي خطأ، أرسل لي
رسالة الخطأ كاملة من سجل Actions وسأصلحه.
